# 制作流程（Workflow）

一条视频从选画到发布分 10 步。每一步写清楚：做什么、用哪个脚本、产出什么、怎么检查。
以《星月夜》为例，命令都在仓库根目录执行。

| # | 步骤 | 工具 | 产出 | 耗时（CPU） |
|---|---|---|---|---|
| 0 | 选画 | 人 | 一幅公版画 | — |
| 1 | 方案与分镜 | [STORYBOARDS.md](STORYBOARDS.md) 模板 | 分镜表（时间、画面、2D/3D 状态） | 30 分钟 |
| 2 | 下载高清图 | `scripts/fetch_wikimedia.py` | `img/<name>.jpg` | 1 分钟 |
| 3 | 深度估计 | `scripts/depth.py` | `depth/<name>.npy` | 10–40 秒 |
| 4 | 画作专属预处理 | `scripts/paintings/<name>.py` | 修正后的深度、光源、流向场 | 写脚本 1–2 小时 |
| 5 | 生成 3D 数据 | `scripts/prep_world.py` | `web/data/<name>_*` | 20 秒 |
| 6 | 编排镜头 | `web/film.js` 里的 cut 函数 | 时间线代码 | 1–3 小时（含迭代） |
| 7 | 关键帧预览 | `web/render.js --times` | 低分辨率静帧 | 每张 1–2 秒 |
| 8 | 逐帧渲染 | `web/render.js --range` | `frames/<name>/00000.jpg …` | 1080p 约 3.5 秒/帧 |
| 9 | 字幕、变速、编码 | `caption.py` `retime.py` `encode.sh` | `out/*.mp4` | 几分钟 |
| 10 | 发布 | 剪映 / 抖音 | 配乐、文案、AI 标注 | — |

---

## 0. 选画

好不好做，取决于这幅画能不能自然地"拆开"。按下面 5 条打分，至少满足 3 条再做：

1. **前后层次分明**：有明确的近景主体、中景、远景。例如《星月夜》里柏树在前，村庄和山在中间，天空在最远处。
2. **画里有能动的东西**：天空、水、风、光，可以做"画活了"的开场钩子。
3. **有光源**：星星、月亮、灯、太阳，加光晕和泛光以后最出片。
4. **有能用来遮挡转场的近景**：树、花丛、柳枝。镜头从它们中间穿过就完成一次转场。
5. **笔触鲜明**：厚涂、方向感强的笔触，拆成 3D 笔触云以后好看。笔触太平滑的画（比如莫奈的睡莲水面）放大后会糊。

经验：《星月夜》5 条全满足；《睡莲池》只满足 1、4，所以效果始终不如前者。

## 1. 方案与分镜

先写分镜表，再写代码。分镜表每一行要写：时间段、画面、**2D/3D 状态**（纯 2D / 2D 动画 / 展开中 / 全 3D / 收回中），以及转场靠什么完成。
模板和两个实例在 [STORYBOARDS.md](STORYBOARDS.md)，设计原则在 [DESIGN.md](DESIGN.md)。最重要的三条：

- 第 1 秒就是整幅画，前 3 秒必须有变化（"画活了"）。
- 2D 和 3D 之间不切镜头，用同一个画面连续展开、连续收回。
- 结尾停在整屏原画上，再出画作信息字幕，和开头首尾呼应。

## 2. 下载高清图

```bash
python3 scripts/fetch_wikimedia.py "File:Van Gogh - Starry Night - Google Art Project.jpg" starry --width 3840
```

- 先在 [Wikimedia Commons](https://commons.wikimedia.org) 搜画名，优先选 "Google Art Project" 或博物馆官方上传的版本（颜色准、分辨率高），复制 `File:...` 标题。
- 宽 3000–4000 px 就够。纹理更大，渲染只会更慢，看不出差别。
- 脚本会打印许可证。**不是 Public domain 就不要用。**
- Commons 限流（HTTP 429）是常态，脚本会自动等待重试。芝加哥艺术博物馆的 IIIF 接口有 Cloudflare 拦截，脚本下不了，请改用 Commons 上的同一幅画。

**检查**：打开 `img/<name>.jpg`，看四边有没有露出画布白边、画框或色卡。有的话在第 4 步裁掉。

## 3. 深度估计

```bash
python3 scripts/depth.py starry                    # 默认 Depth-Anything-V2-Base
python3 scripts/depth.py starry --model depth-anything/Depth-Anything-V2-Small-hf   # 商用请用 Small（Apache-2.0）
```

输出的 `depth/<name>.npy` 是相对视差：0 = 最远，1 = 最近。`depth/<name>_vis.png` 越白越近。

**检查** `depth/<name>_vis.png`：
- 主体轮廓清楚吗？（柏树应该是一整块白色剪影）
- 天空是不是一整片均匀的暗色？模型经常把漩涡、云、星星当成近处物体，这要在第 4 步用遮罩压平。
- 地面应该从下往上由白变暗；如果不是，说明模型把画看成了平面，可以换 Large 模型，或者在第 4 步手画深度。

## 4. 画作专属预处理（最花心思的一步）

单张画的深度一定有错，而且每幅画错得不一样，所以每幅画单独写一个脚本：`scripts/paintings/<name>.py`。复制 `starry_night.py` 改，它做了 5 件事：

1. **裁边**：去掉画布白边。
2. **用遮罩修深度**：
   - 天空 = 一个光滑、略倾斜的远景壳（深度 0.02–0.08）。没有这一步，天空会凹凸不平，展开时漩涡会被撕裂。
   - 近景主体（柏树）= 最大的连通近景块，保持模型给的深度。
   - 地面和村庄 = 中景，强制不比天空更远。
   - 天际线用几个 (u, v) 点手工描出来，比模型分割稳定得多。
3. **光源**：星星、月亮的位置和半径手工标注，窗灯用"黄色 + 亮 + 在村庄范围内"自动检测，写进 `web/data/<name>_lights.json`。渲染时会变成会呼吸的光晕，加上泛光。
4. **笔触流向场**（让画"活"起来的关键）：
   - 用结构张量算出每个位置的笔触方向。这一步只能得到方向的那条线，不知道往哪头走。
   - 再画一个"设计好的参考流向"：整体向右的风、两个大漩涡、每颗星星周围的小漩涡。笔触方向取和参考流向同向的那一头。
   - 输出 `web/data/<name>_flow.png`（R/G = 方向，B = 强度）。天空强、山弱、村庄不动、柏树向上轻微抖动。
5. **调用通用的 `prep_world()`，再修前景主体背后的问题**：镜头一侧移，柏树背后会露出原本被挡住的地方。把这块背景层的深度设成天空，颜色借用旁边的天空；画布外镜像出来的区域也不能出现第二棵柏树。

**检查** `debug/` 里的图：
- `<name>_depth.png`：天空平滑，主体干净。
- `<name>_flow.jpg`：箭头沿着笔触走，漩涡方向和画里一致，黄圈套住每颗星星。
- `<name>_bg.jpg`：主体背后被填成了合理的颜色，不是灰块，也没有重复的教堂尖顶之类。

## 5. 生成 3D 数据

`starry_night.py` 已经调用过了。普通的画可以直接跑：

```bash
python3 scripts/prep_world.py allee                         # 默认网格 420 列、3 万笔触、外延 0.22
python3 scripts/prep_world.py starry --grid 640 --strokes 70000 --margin 0.45 --tex-width 0 --edge-dilate
```

先在 `web/data/worlds.json` 里给这幅画加一条参数（含义见 [REFERENCE.md](REFERENCE.md)）。最关键的是 `zn`/`zf`/`gamma`：
- `zf / zn` 越大，纵深越夸张。天空类的画用 30 左右，室内或近景用 6–10。
- `gamma` > 1 会把中景往远处推，让近景更突出。

### 深度渲染原理（为什么 2D 和 3D 能无缝衔接）

- 每个顶点都放在"相机原点穿过这个像素的那条射线"上，只是离相机的距离不同。所以从原点（画家视角）看出去，3D 场景投影回来**正好就是原画**。
- `uFlat` 控制距离：0 = 所有点都在画布平面（就是一张平面画），1 = 按深度散开。在 0 和 1 之间平滑过渡，就是"展开"和"收回"，中间不需要切镜头，也不会出现跳变。
- 深度突变处（柏树边缘）前景网格的三角形会被拉得很长，着色器把它们丢掉（`worlds.json` 里的 `edge` 阈值），后面的背景层（一个光滑的"远景包络"）补上空洞。
- 笔触粒子从画上采样，颜色取自原画对应位置，方向沿着画的笔触。在 3D 里它们是一片悬浮的笔触云，从画家视角看又拼回原画。

## 6. 编排镜头

镜头写在 `web/film.js` 里，每个 cut 是一个函数 `xxxShot(t)`，输入时间（秒），返回这一帧的相机和效果参数。复制 `starryShot` 改：

```js
function starryShot(t) {
  const w = worlds.starry;
  w.set({ uFlat: ramp(t, 4.0, 7.5) * (1 - ramp(t, 24.6, 27.0)),   // 4–7.5 s 展开，24.6–27 s 收回
          uVol: ..., uFlowAmt: ..., uGlow: ..., uStrokeA: ..., uTime: t });
  const pos = track([[4.0, HOME], [6.0, [0.1, -0.2, -2.0]], ...], t);   // 相机位置关键帧（Catmull-Rom 插值）
  const look = track([[4.0, HLOOK], ...], t);                          // 相机看向的点
  return { sh: { scene: w.scene, pos, look, hfov, focus, aper, bloom, ... }, zoom, fade, cur: null };
}
```

要点：
- **`ramp(t, a, b)`** 是 a→b 秒之间从 0 平滑过渡到 1。所有效果都用它控制淡入淡出，不要用硬开关。
- **相机路径**：先在纸上标出关键点再写坐标。世界坐标里相机在原点、朝 −z 看；画布在 z = −D；天空在 z ≈ −30 到 −60。某个像素 (u, v) 在深度 z 处的位置是 `x = (u−0.5)·2·tanX·z`、`y = (0.5−v)·2·tanY·z`。
- **"画家视角"HOME**：相机在原点，`hfov` 略小于画的 `fov`，画面就被裁成铺满 16:9 的整屏原画。开头和结尾都停在这里。
- **景深**：`focus` 设成相机到注视点的距离，`aper` 在展开过程中从 0 慢慢加到 0.03–0.08。
- **速度感**：`zoom`（径向模糊）只在冲刺段打开（0.02–0.06）；穿过遮挡物的瞬间可以拉到 0.1–0.25。
- 新 cut 要在文件末尾登记：`SHOTS` 里写 cut 名 → 函数，`NEEDS` 里写它需要加载哪些画。

## 7. 关键帧预览（每改一次镜头都做）

```bash
node web/render.js --cut starry --out frames/check --w 960 --h 540 --times 0.5,2.5,5,6.5,8,10,12,15,17,19,21,23.5,24.6,26,29
python3 scripts/contact_sheet.py frames/check sheet.jpg      # 拼成一张大图对照着看
```

每次改完镜头都要看一遍，重点看：
- **转折点**的前后各一帧：展开开始、穿过遮挡物、开始收回、定格。
- 画面边缘有没有露出画布外的东西、灰块、拉伸条纹（对照 [TROUBLESHOOTING.md](TROUBLESHOOTING.md)）。
- 光晕有没有被切成半圆，近处有没有放大成色块的笔触。
- 最后一帧和第一帧是不是同一幅画、同样的构图。

**调试开关**：`render.js --debug noFg` / `noBg` / `noSt` / `noGl`（可以用逗号组合）分别关掉前景深度网格、背景层、笔触、光晕。出现瑕疵时逐层关掉，就能知道是哪一层产生的。

## 8. 逐帧渲染

```bash
node web/render.js --cut starry --out frames/starry --range 0 32 --fps 30            # 1080p
node web/render.js --cut starry --out frames/starry --range 0 32 --fps 30 --gpu      # 有显卡的电脑
```

- 1080p 纯 CPU 约 3.5 秒/帧，30 秒视频约 1 小时。可以放后台跑，中断后重跑会自动跳过已有的帧。
- 只改了后半段镜头时，删掉对应编号以后的帧再重跑，前面的不用重渲。
- 先用 `--w 960 --h 540` 渲一版完整的低清视频，确认节奏没问题再出 1080p。

## 9. 字幕、变速、编码

```bash
python3 scripts/caption.py frames/starry frames/starry_cap --start 26.6 --end 31.5 \
  --line1 "文森特·梵高 ｜《星月夜》 1889年 ｜ 布面油画" --line2 "现藏于纽约现代艺术博物馆（MoMA），73.7 cm × 92.1 cm"
scripts/encode.sh frames/starry_cap out/starry_night.mp4 30 7000k
```

- 字幕信息（年代、材质、馆藏、尺寸）必须到博物馆官网核对。
- 想整体加速但保留重点：`retime.py --segments "0:7:2.0,7:18:1.1,..."`，重点段 1.0–1.1 倍，铺垫段 1.5–2 倍，变速会平滑过渡。
- 体积：聊天软件常有 30 MB 上限，30 秒 1080p 用 7000k 约 27 MB；只发抖音可以用 10000–12000k。

## 10. 发布

- 在剪映里加配乐。转场点（展开、穿过遮挡、定格）尽量卡在节拍上，`retime.py --marks` 能打印旧时间点在新时间线上的位置。
- 抖音发布时勾选"内容由 AI 生成"。
- 文案方向：沉浸感 / 悬念（"第 13 秒我掉进了画里"）/ 知识点，画作信息放在正文末尾或评论区置顶。
- 系列化：同一套流程每期换一幅画，评论区征集"下一期想走进哪幅画"。
